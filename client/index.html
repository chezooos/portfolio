1. About me

안녕하세요, 백엔드 개발자를 꿈꾸는 김영은입니다.

세명컴퓨터고등학교 인공지능소프트웨어과에서 공부하고 있습니다. 화면에서 보낸 요청이 서버에서 어떻게 처리되고, 데이터가 어디에 저장되는지 알아가는 게 재미있습니다. Spring Boot로 게시판을 만들고 MySQL을 연결한 뒤 AWS에 직접 배포하면서, 제가 만든 서비스가 실제로 동작하기까지 어떤 과정이 필요한지 배웠습니다.

산업현장 안전 프로젝트에서는 팀장을 맡아 팀원들과 기획부터 발표까지 함께했고, 센서 회로와 체결 상태를 판단하는 코드를 담당했습니다. 개발 중에 문제가 생기면 어디서부터 잘못됐는지 하나씩 확인해 보는 편입니다.

앞으로는 사람들이 실제로 쓰는 서비스를 만들고, 배포한 뒤에도 문제를 찾아 개선할 수 있는 백엔드 개발자가 되고 싶습니다.

2. Skills

2-1. AWS & Cloud

AWS EC2 · RDS · S3 · Elastic IP · Route 53

  • 서버 배포 — EC2 인스턴스에 SSH로 접속해 Spring Boot 애플리케이션을 배포하고, 외부에서 서비스에 접속할 수 있는지 확인했습니다.
  • 데이터베이스 연동 — RDS에 MySQL을 구성하고, EC2에서 실행되는 애플리케이션과 연결했습니다.
  • 파일 저장 — S3 버킷을 만들어 웹 서비스의 파일 저장에 활용했습니다.
  • 접속 설정 — EC2와 RDS의 보안 그룹에서 필요한 포트와 접속 대상을 설정했습니다. SSH 접속 과정에서는 .pem 키 파일의 권한도 확인했습니다.
  • IP와 도메인 — Elastic IP를 EC2에 연결해 고정 IP를 사용하고, Route 53에서 도메인과 서버 주소를 연결하는 설정을 실습했습니다.
  • 그 외 클라우드 경험 — Supabase에서 웹 프로젝트용 테이블 생성을 실습했고, GCP도 학습했습니다.

  • 산업현장 안전 프로젝트에서 이미지 탐지 결과와 Arduino 센서값을 함께 활용하는 방식을 검토했습니다.
  • OpenCV와 SAHI를 학습하며 이미지 처리와 객체 탐지 방법을 익혔고, Pandas·scikit-learn·Keras로 데이터 처리와 머신러닝의 기초를 공부했습니다.

1학년

3-1. 공사장 헬멧 인식 프로젝트

개요

공사 현장의 안전사고 사례를 살펴보면서, 안전모를 제대로 착용했는지 작업 전에 확인하는 과정에 관심을 갖게 되었습니다. 여러 작업자가 오가는 현장에서는 담당자가 모든 사람의 착용 상태를 계속 확인하기 어렵다고 생각했습니다. 이를 보완하기 위해 작업자 이미지에서 안전모를 찾아주는 객체 탐지 기능을 구현하고, Arduino 센서값도 함께 확인할 수 있는 산업현장 안전 시스템을 제작했습니다.

주요 기능

  • 작업자 이미지에서 안전모의 위치를 탐지하고 바운딩 박스로 표시합니다.
  • 탐지 결과를 이미지와 함께 확인할 수 있도록 구성했습니다.
  • Arduino에 연결한 센서의 측정값을 읽어 영상과 별도로 현장 상태를 확인합니다.

사용 기술 — YOLO 객체 탐지 · 바운딩 박스 · Arduino 센서 데이터 수집

동작 흐름 — 작업자 이미지 입력 → YOLO 추론 → 안전모 위치 탐지 → 탐지 결과 표시 / Arduino 센서값 수집 → 측정값 확인

3-2. 인공지능소프트웨어과 해커톤 · 스터디카페 키오스크

개요

해커톤에서 학생들이 일상적으로 사용하는 키오스크 중 어떤 상황에서 가장 많이 헤맬지 생각하다가 스터디카페가 떠올랐습니다. 처음 방문한 학생은 이용권을 먼저 골라야 하는지, 좌석부터 선택해야 하는지 바로 알기 어렵고, 선택한 시간이나 금액을 다시 확인하려면 이전 화면으로 돌아가야 할 수도 있습니다. 그래서 처음 이용하는 사람도 현재 단계와 다음에 할 일을 쉽게 알아볼 수 있는 스터디카페 키오스크를 기획했습니다.

기능 설계

  • 이용권의 시간과 금액을 비교하고, 좌석 배치도에서 선택 가능한 좌석을 확인합니다.
  • 진행 단계를 표시하고, 이전 화면으로 돌아가도 기존 선택이 유지되도록 설계했습니다.
  • 결제 직전 이용권·좌석·금액을 한 화면에서 검토하고 수정할 수 있도록 구성했습니다.

기술 구성안 — 사용자 흐름 설계 · 화면 프로토타이핑 · 단계별 선택 상태 관리 · 이용권 및 좌석 입력 검증

설계 흐름 — 이용 목적 선택 → 이용권 선택 → 좌석 선택 → 이용 내역과 결제 금액 확인 → 결제 단계 진입

3-3. 2025 K-Tech 챌린지 · 전동킥보드 헬멧 착용 확인

개요

전동킥보드 사고 사례를 접하면서, 헬멧 착용을 안내하는 메시지가 있어도 이용자가 실제로 착용했는지 확인하기는 어렵다는 점에 주목했습니다. 주행을 시작하기 직전에 착용 상태를 확인하고, 판정이 어려운 경우에는 다시 촬영하도록 안내하면 이용자가 출발 전에 한 번 더 점검할 수 있다고 생각했습니다. 이를 바탕으로 전동킥보드 이용 과정에 영상 기반 헬멧 착용 확인 절차를 넣는 서비스를 기획했습니다.

기능 설계

  • 이용자가 촬영한 이미지에서 사람과 헬멧을 탐지하고, 헬멧이 머리 영역에 있는지 확인합니다.
  • 조명이 어둡거나 머리 부분이 가려져 판정이 어려우면 재촬영을 안내합니다.
  • 착용 여부에 따라 확인 완료 메시지 또는 헬멧 착용 안내를 표시합니다.

기술 구성안 — 컴퓨터 비전 · 객체 탐지 · 사람과 헬멧의 위치 관계 분석 · 신뢰도 기반 재촬영 안내

설계 흐름 — 주행 전 이미지 촬영 → 사람과 헬멧 탐지 → 머리 영역과 헬멧 위치 비교 → 착용 결과 또는 재촬영 안내 표시

3-4. 2025 구글 ESG · AI 기반 야생동물 도로 진입 감지

개요

통합사회 수업에서 도로를 건너던 야생동물이 차량과 충돌하는 문제를 배웠습니다. 사고가 난 뒤 위치를 기록하는 것에서 한 걸음 더 나아가, 동물이 도로에 접근하는 순간을 먼저 알아차릴 수 있다면 운전자에게 감속할 시간을 줄 수 있겠다고 생각했습니다. 인공지능이 영상에서 야생동물을 찾아내고, 도로와의 위치 관계를 바탕으로 경고가 필요한 상황을 구분하는 시스템을 구상했습니다.

기능 설계

  • 도로 주변 영상에서 야생동물을 탐지하고 화면 속 위치를 확인합니다.
  • 탐지된 동물이 갓길이나 차도에 해당하는 관심 영역에 들어왔는지 판단합니다.
  • 위험 조건이 충족되면 감속 안내를 표시하고, 탐지 시각과 구간을 기록하도록 설계했습니다.

기술 구성안 — 영상 기반 객체 탐지 · 관심 영역(ROI) 설정 · 영역 진입 판정 · 탐지 이벤트 기록

설계 흐름 — 도로 주변 영상 입력 → 야생동물 탐지 → 도로 관심 영역 진입 여부 확인 → 감속 안내 → 탐지 기록 저장

3-5. 전공 자율 동아리 · 스팸 메일 분류

개요

받은편지함에 광고나 스팸 메일이 쌓일 때마다 필요한 메일을 찾는 데 시간이 걸렸습니다. 스팸 메일마다 제목은 다르지만, 특정 단어나 표현이 반복된다는 점이 눈에 들어왔습니다. 제목과 본문의 특징을 컴퓨터가 학습하면 새 메일도 자동으로 분류할 수 있을지 궁금해져, 전공 자율 동아리에서 스팸 메일 분류를 주제로 탐구하고 발표했습니다.

기능 설계

  • 메일 제목과 본문을 전처리하고, 단어의 중요도를 수치로 표현합니다.
  • 학습한 분류 모델로 새 메일이 스팸인지 일반 메일인지 예측합니다.
  • 일반 메일을 스팸으로 잘못 분류한 사례와 스팸을 놓친 사례를 구분해 확인합니다.

기술 구성안 — Python · 텍스트 전처리 · TF-IDF · 나이브 베이즈 분류 · 정밀도·재현율 평가

설계 흐름 — 분류 기준이 표시된 메일 데이터 준비 → 학습·평가 데이터 분리 → 텍스트 전처리 및 TF-IDF 변환 → 분류 모델 학습 → 예측 결과와 오분류 사례 분석

3-6. 화면 구현 발표 · 따릉이 대여소 지도

개요

따릉이를 타고 이동하다가 반납할 곳을 바로 찾지 못해 이용 시간을 넘기고 추가요금을 낸 적이 있습니다. 그때 필요한 건 서울 전체 대여소 목록이 아니라, 지금 있는 곳에서 어디로 가야 가장 빨리 반납할 수 있는지 보여주는 화면이었습니다. 이 경험을 바탕으로 현재 위치와 주변 대여소를 한눈에 비교할 수 있는 따릉이 지도를 만들고, 화면 구현 과정을 발표했습니다.

기능 설계

  • 지도에 사용자 위치와 주변 대여소를 함께 표시합니다.
  • 주변 대여소를 직선거리 기준으로 정렬해 가까운 곳부터 비교할 수 있도록 구성했습니다.
  • 지도에서 대여소를 선택하면 대여소 이름과 주소, 현재 위치에서의 거리를 확인할 수 있도록 설계했습니다.

기술 구성안 — 웹 지도 API · 브라우저 위치 정보 API · 대여소 좌표 데이터 · 지도 마커 · 위도·경도 기반 거리 계산

설계 흐름 — 현재 위치 또는 기준 위치 설정 → 대여소 좌표 불러오기 → 거리 계산 및 정렬 → 지도에 마커 표시 → 선택한 대여소의 상세 정보 확인

3-7. AWS 특강 · 대전 맛집 지도

개요

대전 출신이라고 소개할 때마다 친구들이 가장 먼저 “성심당!”을 외치는 게 재미있었습니다. 그러다 대전을 처음 방문하는 친구에게 성심당 외에도 제가 알고 있는 식당과 카페를 위치와 함께 알려주면 좋겠다는 생각이 들었습니다. 그래서 대전의 맛집을 지도 위에서 찾아볼 수 있는 웹 서비스를 만들었습니다. 프로젝트를 포트폴리오에 정리하면서 화면에 표시되는 맛집 정보가 서버와 데이터베이스를 거쳐 전달되는 구조도 함께 다뤘습니다.

기능 설계

  • 맛집을 지도에 표시하고, 지역이나 음식 종류에 따라 원하는 장소를 찾아볼 수 있도록 구성했습니다.
  • 지도에서 장소를 선택하면 이름과 주소, 간단한 소개를 볼 수 있도록 설계했습니다.
  • 맛집 정보와 사진을 분리해 저장하고, 서버에서 필요한 정보만 조회해 화면에 전달하는 구조를 구상했습니다.

기술 구성안 — Spring Boot · MySQL · 웹 지도 API · AWS EC2 서버 배포 · Amazon RDS 데이터 저장 · Amazon S3 이미지 저장

설계 흐름 — 사용자가 지역이나 음식 종류 선택 → Spring Boot 서버에 조회 요청 → 데이터베이스에서 조건에 맞는 맛집 정보 조회 → 지도에 표시 → 장소 선택 시 상세 정보 확인

3-8-2. 2차 · 모의 주식 투자 게임

개요

주식 투자를 하다가 손실을 본 경험을 계기로, 가격이 바뀔 때마다 내 자산이 왜 늘거나 줄었는지 먼저 연습해 볼 수 있으면 좋겠다고 생각했습니다. 실제 돈을 쓰지 않고도 주문 수량을 정하고, 매수 후 가격이 변하면 평가손익이 어떻게 달라지는지 확인할 수 있는 모의 투자 게임을 만들었습니다. 매매 자체에 그치지 않고, 거래 기록을 돌아보며 어떤 판단이 결과에 영향을 줬는지 살펴볼 수 있도록 기획했습니다.

기능 설계

  • 가상 자금으로 종목을 선택하고 매수·매도 주문을 입력합니다.
  • 보유 현금이나 주식 수량을 초과하는 주문을 확인하고, 정상 주문은 잔액과 보유 내역에 반영합니다.
  • 현재 평가금액과 손익을 계산하고, 이전 거래를 내역에서 확인합니다.

기술 구성안 — 시세 데이터 처리 · 주문 유효성 검사 · 잔액 및 보유 수량 관리 · 평가손익 계산 · 거래 이력 관리

설계 흐름 — 가상 자금 설정 → 종목과 가격 확인 → 매수·매도 주문 입력 → 주문 가능 여부 검사 → 잔액·보유 수량 갱신 → 평가손익과 거래 내역 확인

3-9. 미래인재 활동 · AI 자기소개서 검토 서비스

개요

취업이나 대학 진학을 준비하는 친구들이 자기소개서를 쓸 때, 어떤 경험을 골라야 할지보다 이미 적은 경험을 어떻게 더 구체적으로 설명할지 막막할 수 있다고 생각했습니다. 바로 첨삭을 받기 어려운 상황에서도 스스로 초안을 점검할 수 있도록, 문항의 의도와 작성한 답변을 함께 분석하는 AI 자기소개서 검토 서비스를 개발했습니다. 작성자가 자신의 경험을 살려 직접 수정할 수 있도록, 보완이 필요한 문장과 이유를 보여주는 데 초점을 맞췄습니다.

기능 설계

  • 지원 유형과 자기소개서 문항, 작성한 답변을 함께 입력받습니다.

기술 구성안 — 대규모 언어 모델(LLM) · 평가 기준 기반 프롬프트 설계 · 구조화된 피드백 출력 · 입력값 검증

설계 흐름 — 지원 유형 선택 → 문항과 답변 입력 → 평가 기준에 따라 AI 검토 → 항목별 피드백 표시 → 사용자가 답변 수정

3-10. LG AI 지니어스 아카데미 · 공사장 안전모 착용 판정

개요

공사 현장의 사고 사례를 보며, 영상에 안전모가 보이는 것과 작업자가 실제로 안전모를 쓰고 있는 것은 구분해야 한다고 생각했습니다. 화면 한쪽에 놓여 있는 안전모까지 착용으로 판단하면 안전 점검에 활용하기 어렵기 때문입니다. LG AI 지니어스 아카데미에서는 이 문제에 초점을 맞춰, 작업자와 안전모의 위치를 함께 살펴보고 거리나 가림에 따라 판정이 어떻게 달라질 수 있는지 정리했습니다.

기능 설계

  • 한 이미지에서 작업자와 안전모의 위치를 각각 탐지합니다.
  • 여러 작업자가 등장할 때 각 작업자의 머리 영역과 안전모 위치를 비교해 착용 여부를 구분합니다.
  • 머리 부분이 가려지거나 탐지 신뢰도가 낮으면 확인이 필요한 사례로 분류합니다.

기술 구성안 — YOLO 기반 객체 탐지 · 바운딩 박스 위치 비교 · 탐지 신뢰도 기준 설정 · 오탐 및 미탐 사례 분석

설계 흐름 — 공사 현장 이미지 입력 → 작업자와 안전모 탐지 → 작업자별 머리 영역과 안전모 위치 비교 → 착용 또는 확인 필요 상태 표시 → 오탐·미탐 사례 검토

3-11. AI·로봇 안전제어 솔루션 챌린지 · 스마트 안전고리

개요

고소 작업 사고 사례를 살펴보면서, 작업자가 안전고리(카라비너)를 걸었다고 생각해도 게이트가 완전히 닫혔는지 확인하는 절차를 놓칠 수 있다는 점에 주목했습니다. 작업자가 체결 상태를 다시 확인할 수 있도록 사진과 센서값을 함께 살펴보는 점검 방식을 기획했습니다. 저는 4인 팀의 팀장과 하드웨어 담당을 맡아, 압력과 기울기 센서의 신호를 읽고 설정한 조건에 따라 LED로 경고하는 프로토타입을 제작했습니다.

주요 기능

  • FSR 압력 센서로 게이트에 가해지는 압력을 읽고, 측정값이 기준을 넘으면 검사를 시작합니다.
  • 검사 시작 시점의 기울기 상태를 저장한 뒤, 압력이 유지되는 동안 SW-200D 센서의 상태 변화가 있었는지 확인합니다.
  • 센서 상태가 설정한 경고 조건에 해당하면 LED를 점등해 작업자에게 재확인을 안내합니다.

사용 기술 — Arduino Nano ESP32 · Arduino C++ · FSR 압력 센서의 아날로그 입력 · SW-200D 기울기 센서의 디지털 입력 · LED 제어

동작 흐름 — 압력값 측정 → 기준값 도달 시 기울기 초기 상태 저장 → 압력이 유지되는 동안 기울기 입력 확인 → 경고 조건 충족 시 LED 점등

3-12. 자료구조 수행평가 · 지하철 노선 경로 탐색

개요

지하철 노선도를 보면서 출발역과 도착역 사이에 여러 경로가 있을 때, 길찾기 프로그램은 그중 하나를 어떻게 고르는지 궁금했습니다. 역과 역 사이의 연결을 자료구조로 표현하면 노선도를 직접 따라가지 않아도 컴퓨터가 경로를 찾을 수 있다고 생각했습니다. 수행평가에서는 먼저 문제를 ‘정차역 수가 가장 적은 경로 찾기’로 정의하고, 지하철 노선을 그래프로 표현해 탐색하는 방식을 적용했습니다.

기능 설계

  • 출발역과 도착역을 입력받고, 등록된 역인지 확인합니다.
  • 역을 정점으로, 인접한 역 사이의 연결을 간선으로 구성합니다. 환승역에서는 연결된 노선도 탐색할 수 있도록 합니다.
  • 출발역에서 가까운 역부터 탐색하고, 도착역을 찾으면 지나온 역을 순서대로 출력합니다.

기술 구성안 — 그래프 · 인접 리스트 · 너비 우선 탐색(BFS) · 큐 · 방문 기록 · 이전 역 기록을 이용한 경로 복원

설계 흐름 — 노선 연결 데이터로 그래프 구성 → 출발역과 도착역 입력 → 큐를 이용해 인접역 탐색 → 도착역 발견 → 이전 역 기록을 역순으로 추적 → 전체 이동 경로 출력
